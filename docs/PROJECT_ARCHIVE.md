## 1. 为什么建立 SCU LENS

四川大学摄影协会已经长期使用 QQ 频道承载真实内容：活动通知、相机组投稿、手机组投稿、胶片组投稿、每月九图、讨论与求助等。

QQ 频道适合：

- 高频发布；
- 投稿；
- 社区讨论；
- 即时通知；
- 成员互动。

但频道的消息流不适合长期承担：

- 作品策展；
- 摄影档案；
- 历届活动沉淀；
- 每月九图的长期归档；
- 对外统一展示；
- 招新与合作入口。

因此 SCU LENS 的定位不是“再造一个 QQ 频道”，而是：

> **把频道里的内容，从消息流整理成可长期查看的摄影档案。**

核心原则：

1. **频道发生，网站沉淀。**
2. **照片优先，功能其次。**
3. **投稿不重复。** 投稿继续发生在 QQ 频道。
4. **自动搬运，人工策展。** 后续通过 QQ Bot / 内容池减少人工下载上传，但正式收录与策展仍由协会决定。
5. **长期可交接。** 网站结构、内容模型、部署流程必须能被下一届继续维护。

## 2. 当前站点职责

### SCU LENS 网站

负责：

- 协会对外形象；
- 精选摄影作品；
- 每月九图；
- 活动档案；
- 加入我们；
- 关于协会；
- QQ 频道与合作组织的统一入口；
- 后续作者页、作品页、成员认证与管理后台。

### QQ 频道

负责：

- 日常分享；
- 相机 / 手机 / 胶片投稿；
- 活动通知；
- 即时交流；
- 非投稿区与问题求助；
- 每月九图征集。

### 二者未来的关系

```text
QQ 频道
  ↓
QQ Bot / Sync
  ↓
频道内容池
  ↓
人工收录 / 策展
  ↓
SCU LENS 正式档案
```

网站不应直接长期热链 QQ CDN 图片。未来正式自动化时，图片应复制到协会自己的对象存储（计划腾讯 COS），数据库只保存内容关系与来源信息。

## 3. 技术选型

### 当前技术栈

- Astro 7
- TypeScript
- Static Output
- GitHub
- Tencent EdgeOne Pages / Makers
- 自定义域名：`sculens.leftjun.com`

### 为什么第一阶段使用 Astro 静态站

当前首要任务不是登录系统，而是确定：

- 内容架构；
- 视觉语言；
- 摄影作品展示方式；
- 每月九图层级；
- 活动与协会档案的长期结构。

静态站有这些优势：

- 结构简单；
- 部署稳定；
- 页面速度快；
- 维护成本低；
- 适合先大量试 UI；
- 不需要在视觉结构未定时过早绑定数据库。

### 为什么未来可能变成混合 / 动态架构

后续计划包含：

- 川大校园身份认证；
- 成员账号；
- 管理员白名单；
- 内容管理后台；
- 频道内容池；
- QQ Bot 自动同步；
- 作者与作品关联；
- 自动生成每月九图与活动档案。

因此最终形态可能变成：

```text
Astro / 前端展示
        ↓
API / 内容服务
        ↓
数据库 + COS
        ↑
QQ Bot / 校园认证 / 管理后台
```

当前**不要为了未来动态化而提前推翻前端**。先把内容模型与页面层级做对。

## 6. 每月九图内容模型

### 6.1 总览页

`/monthly-nine`

这里只做**摘要**。

每一期占一个大卡片 / 大展览单元，主要展示：

- 年月；
- 主题；
- 英文副题；
- 一段摘抄；
- 代表视觉；
- 入选作品数量；
- 查看本期。

总览页不承载完整征集文案、完整获奖公告。

### 6.2 月份 / 主题详情页

例如：

`/monthly-nine/2025-yellow`

这里必须是**完整档案**，不是摘要。

需要包含：

- 完整主题名称；
- 完整主题文案；
- 征集说明（如果有）；
- 公布时间；
- 完整获奖 / 入选信息；
- 每件作品；
- 作品标题；
- 摄影者；
- 图片；
- 下一期主题；
- 原始频道来源（未来可补 message id）。

### 6.3 单图作品

在主题详情页直接完整展示原图。

不强制裁成相同比例。

原则：

> 图片保持原始比例，网页排版为图片服务。

### 6.4 多图 / 图集作品

主题详情页中，多图作品只作为**一个作品单元**。

例如：

```text
03
[主图] [+9]

《金黄色的》
摄影 / 三川

查看完整组图 →
```

点开后进入单独组图页。

组图页：

- 保留作品名称；
- 作者；
- 所属每月九图；
- 完整图片序列；
- 根据横竖比例进行摄影刊物式错落排版；
- 不强行九宫格；
- 不把一组照片错误计为多个入选作品。

## 9. 视觉语言

当前方向：

- 米白 / 黑 / 暖灰；
- 编辑部 / 摄影刊物感；
- 大字号 Serif 标题；
- 小型英文 Eyebrow；
- 高留白；
- 图片优先；
- 避免企业官网卡片感；
- 避免 QQ Feed 式头像 / 点赞 / 评论噪音；
- 作品尽量保留原始比例；
- 总览可使用不规则拼版；
- 详情页给单张照片足够呼吸空间；
- 图集采用杂志式错落排版。

当前仍属于**框架建设期**，视觉并未锁定。

## 14. 未来动态化方向

最终账号层级建议：

```text
访客
  ↓
校园认证用户
  ├─ 学生
  └─ 老师
       ↓
成员
       ↓
管理员
```

管理员不是独立身份体系，而是成员 / 校园认证用户之上的权限角色。

管理员权限未来可使用白名单配置。

校园认证目标：

- 不保存川大账号密码；
- 优先研究四川大学官方统一身份认证 / OAuth / CAS 能否合法接入；
- 只使用官方可授权流程；
- 不通过代填密码、抓取密码的方式实现。
